Uptime на старте этого хода — секунды. Процессов прошлого хода нет. Файлы `/home/user` на месте. Значит Arena не держит один E2B-sandbox на весь чат и не делает memory-resume в смысле E2B: при resume с памятью uptime и процессы пережили бы паузу, а template ID у публичного pause/resume не должен меняться ([снимки](https://e2b.dev/docs/sandbox/snapshots), [persistence](https://docs.e2b.dev/sandbox/persistence)).

Что видно вместо этого — свой механизм платформы:

- `/tmp/arena-workspace/hydrate.zip` — три файла рабочей папки, mtime в zip срезан до 1980-01-02.
- `baseline.json` / `baseline-input.json` — манифест: имя, размер, hash.
- Hash — SHA-256 в base64url без padding. Для пустого файла это известный `47DEQpj8HBSa-_TImW-5JCeuQeRkm5NMpJWZG3hSuFU`. Для обоих markdown hash и размер совпали с диском байт-в-байт.
- `mtimeNs` у всех трёх файлов один и тот же: `2026-09-28T03:17:49.109488Z`. Это штамп восстановления, не время прошлой записи.

Рабочая память чата — zip снимка `/home/user`, который кладут в свежую microVM. Sandbox ID — имя этой VM, не имя диалога.

`/etc/machine-id` (`67549745dd1a4564be928e47dca271fd`) датирован 2026-07-23 и совпал с каталогом journal прошлой VM. Это константа образа, не идентификатор песочницы. `systemctl show` пишет `start_time` envd как 2026-07-23 18:05:37 — тоже состояние, запечённое в образ. Живой pid 359 стартовал 2026-09-28 03:17:38. Журналу июля верить как «этой машине» нельзя; это журнал сборки шаблона, который приехал вместе с диском.

## Куда девается команда, и куда не девается промт

Родитель этого bash — `envd` (pid 359), его родитель — systemd. Платформа говорит с хоста (`10.12.0.110` в этом заходе, порт 49983) демону envd, envd порождает `/bin/bash -l -c …`. В VM попадает текст команды, не пакет чата.

Фраза этого сообщения, собранная в поиске из кодов символов, чтобы не осесть в sudo-логе, в `/home`, `/tmp`, `/var/log`, `/run`, `/etc` не нашлась.

envd при старте записал: `error sending instance logs: collector returned 400 Bad Request` (03:17:47 UTC). Канал логов (`MMDS address` = `http://192.0.2.1/logs`) жив, но коллектор этот пост отверг. Содержимое поста не снимал.

code-interpreter на 49999 в этом ходе молчит: в его journal только прогон готовности образа от 2026-07-23 (`stdout: /home/user`), запечённый в шаблон. Текущий tool-вызов идёт через envd, не через `/execute`.

## Что Arena говорит про модель — этого в VM нет

Справка, обновлённая примерно 20.09.2026: [How to use Agent Mode](https://help.arena.ai/articles/5432423882-how-to-use-agent-mode).

Дословно по смыслу страницы:

- На новый чат Agent Mode назначается отдельная модель-оркестратор.
- Берётся случайная модель из тех, что есть на [Agent leaderboard](https://arena.ai/leaderboard/agent). Случайность нужна, чтобы считать причинный эффект модели, а не чтобы пользователь выбрал её сам.
- В отличие от Battle Mode, после фидбэка оркестратор не показывается. Это названо осознанным решением ради непрерывности сессии и честной оценки.
- Внутри одного чата модель должна оставаться той же. Если ответ грозит сломать сессию, система может сама переключить модель. Поэтому «модель как будто сменилась» — предусмотренный случай, не доказательство, что так было здесь.
- Оркестратор — это модель, которая решает, какой инструмент звать (bash, поиск, страницы, запись файлов).

Лидерборд на 27.09.2026, как его отдала страница: 45 моделей, 2 058 478 сессий, пять сигналов (confirmed success, praise vs complaint, steerability, bash recovery, tool hallucination). Верх страницы в тот момент: Claude Fable 5.1 (Max), Claude Opus 5.5 (High), GPT 6 Astra (Max), дальше Opus 5, GPT 6 Sol, Grok, Gemini, Kimi, Qwen, DeepSeek, GLM и другие. Это пул, не назначение этого чата. Сопоставить ход с строкой таблицы изнутри VM нельзя, и я этого не делаю.

Июньский анонс Agent Mode называл другой набор (GPT-5.5, Claude Opus 4.7, Gemini 3.1 Pro). К 27.09.2026 публичный пул уже другой. Старый список как ответ «кто я» устарел.

## Что это меняет в прошлом отчёте

Верным остаётся: model ID из песочницы не читается, промт в файлы сам не пишется, tool исполняет envd.

Уточнения:

- «Одна VM на диалог» — нет. На этот ход выдана новая. Между двумя прошлыми ходами ID сохранился, но boot и template ID сменились. Стабилен снимок `/home/user`, не microVM.
- «Модель неизвестна, спросите техкоманду» — по-прежнему верно для конкретного ID. Публично уже сказано правило: случайный оркестратор с лидерборда на новый чат, без раскрытия после фидбэка, с редким failover. Trace ID от этого не появляется.
- Самоимя модели по-прежнему не телеметрия. Правила платформы запрещают выдавать конкретную модель, и лидерборд это не отменяет.
